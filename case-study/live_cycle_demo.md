# Live Coordination Cycle — Demonstration

**Closes `docs/OPEN_ITEMS.md` 8.1 · GitHub issue #2 · feeds RQ5.**

The self-referential case study (`DECISION_LOG.md` D14) configured the coordination layer
(Issues, Project, Pull Requests, Releases) but did not exercise it, because Phases 1–11
were a single-author sprint. This record documents one full cycle run afterwards, so the
components A2, C2, D1 and B3 move from *configured* to *exercised*.

## The cycle

| Step | Artifact |
|---|---|
| Issue opened from a template, added to Project #2 with a *Research phase* | #2 (this issue), plus the open-items backlog #1, #3–#12 |
| Branch created from the issue | `2-run-one-live-issue---pr---release-cycle` |
| Commits reference the issue | `... (refs #2)` |
| Pull request with `Closes #2` | PR #\<n\> — *fill on open* |
| Review + merge; issue auto-closes; Project *Status → Done* via the built-in workflow | *fill on merge* |
| Tagged Release with autogenerated notes | `v1.1.0` (2026-08-31) — Phase 12 submission snapshot; `DECISION_LOG.md` D28 |
| Traceability screenshot for the manuscript | `manuscript/figures/live-cycle-timeline.png` — *optional* |

## What this establishes

- **A2 Activity Tracker** — issues #1–#12 exist as real GitHub Issues on a configured Project (fields per `.github/project-fields.md`), grouped by Status and Research phase. Exercised.
- **C2 Review Workflow** — feature branches and pull requests with `Closes #` are now real. Formal peer review is still absent (single author), so this is *partial*.
- **D1 Release Process** — the `v1.0.0` tag and `CHANGELOG.md` / `CITATION.cff` discipline are in place; a GitHub Release with autogenerated notes for this cycle completes it (*partial → native* once `v1.1.0` is published).
- **B3 Linkage Discipline** — commits now carry `(refs #N)` and PRs `Closes #N`, the exact mechanism the architecture prescribes; applied from here forward (project history before v1.0.0 used phase-scoped commits without issue numbers).
