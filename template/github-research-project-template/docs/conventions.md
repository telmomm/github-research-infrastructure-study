# Working Conventions

These four conventions turn generic GitHub features into research-usable support for planning, research-question tracking, decision traceability and provenance. They are **not optional**: without them the coordination and record layers do not connect.

Each convention names the architecture component it operationalises (A1, A3, B2, B3).

---

## 1. Phased-plan convention (component A1 — Research Plan)

- The Project has a single-select field **Research phase** with exactly this vocabulary:
  `Idea · Question · Planning · Literature · Methods · Data · Analysis · Results · Manuscript · Publication · Outputs`
- Each phase has a **milestone** of the same name.
- **`docs/roadmap.md` is the plan of record.** It is edited (committed) whenever the plan changes; its history *is* the plan's revision history.
- Every issue is assigned a Research phase and a milestone when it is created.

## 2. Question-register convention (component A3 — Question Register)

- Every research question is a dedicated issue titled **`RQ-n: <question>`** with the `research-question` label (or Issue Type `Question` if your org has it).
- Issue **#1 is the RQ index** and is pinned; it lists every `RQ-n` with a one-line status.
- Every method, analysis or manuscript issue and PR **references the RQ issue(s)** it serves (`Refs #<rq>`).
- Reformulating a question is a timeline comment on its issue, prefixed `reformulated:` — do not edit the original text.

## 3. Decision-record convention (component B2 — Decision Log)

A decision is *significant* if reversing it would cost rework or change a result. For each one:

- Add a numbered entry to **`docs/decision-log.md`**: `Dn — title`, date, context, decision, rationale, alternatives considered, affected files/issues.
- Open a **`decision`-labelled issue** that links to the `Dn` entry and cross-references every affected artifact.
- A decision that supersedes an earlier one links back to it (`Supersedes D<k>`).
- Deliberation happens in a **Discussion** (Q&A or Poll); the accepted answer / poll result is referenced from the `Dn` entry.

## 4. Linkage-discipline convention (component B3 — Linkage Discipline)

Mandatory cross-referencing, so any artifact can be traced to any other:

| Action | Rule |
|---|---|
| Commit | message names its issue: `... (refs #123)` |
| Pull request | body contains `Closes #123` (or `Refs #123` if it does not close it) |
| Issue | body names its **RQ** (`Refs #<rq>`) and is on a **milestone** |
| Release | cut from a tag; the autogenerated notes inherit the PR → issue chain |
| External artifact | linked by URL/DOI from the relevant issue and folder README, never copied in |

The end-to-end path this produces:

```
RQ issue → method issue → branch/commits → analysis PR (Closes) → result → manuscript PR → Release → DOI
```
